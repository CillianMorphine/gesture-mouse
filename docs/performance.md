## 1. Методологія профілювання

### 1.1 Інструменти

| Інструмент | Тип | Платформа | Призначення |
|---|---|---|---|
| **Valgrind / Callgrind** | CPU-профілювання | Linux | Точний час виконання функцій, call graph |
| **gprof** | CPU-профілювання | Linux/GCC | Статистика викликів, % часу на функцію |
| **Visual Studio Profiler** | CPU + Memory | Windows | Sampling profiler, timeline |
| **Valgrind / Massif** | Heap profiler | Linux | Використання пам'яті в часі |
| **AddressSanitizer (ASan)** | Memory | Cross | Витоки пам'яті, буферні переповнення |
| **perf** | CPU | Linux | Hardware counters, cache misses |
| **std::chrono (вбудований)** | Timing | Cross | Мікробенчмарки ключових етапів |

**Обраний підхід:** для цієї роботи використовується вбудований профілювальник на базі `std::chrono::steady_clock` (`src/utils/profiler.hpp`), який вимірює кожен етап конвеєра обробки кадру. Це дозволяє отримати точні дані без overhead зовнішніх інструментів і без необхідності повторного збирання з debug-символами.

Для запуску зовнішнього профілювання (рекомендується для повного аналізу):

```bash
# Linux — Callgrind
g++ -O1 -g -std=c++17 src/*.cpp -o gesture_mouse $(pkg-config --cflags --libs opencv4)
valgrind --tool=callgrind --callgrind-out-file=callgrind.out ./gesture_mouse
kcachegrind callgrind.out  # візуалізація

# Linux — gprof
g++ -pg -O1 -std=c++17 src/*.cpp -o gesture_mouse_gprof $(pkg-config --cflags --libs opencv4)
./gesture_mouse_gprof
gprof gesture_mouse_gprof gmon.out | gprof2dot | dot -Tpng -o callgraph.png

# Linux — AddressSanitizer (витоки пам'яті)
g++ -fsanitize=address -g -std=c++17 src/*.cpp -o gesture_mouse_asan $(pkg-config --cflags --libs opencv4)
./gesture_mouse_asan
```

## 3. Оптимізації

### Оптимізація 1 — Downscale перед обробкою (ROI Resize)

**Файл:** `src/gesture/gesture_detector_optimized.cpp`

**Проблема:** Усі три гарячі точки обробляють повний кадр. Для 1280×720 це 921 600 пікселів. Для виявлення руки (грубого сегментування) така точність надлишкова.

**Рішення:** Перед HSV-конвертацією зменшити кадр до 320×240 (`cv::resize`). Це зменшує кількість оброблюваних пікселів у **9 разів** (320×240 = 76 800).

```cpp
// ДО оптимізації:
cv::Mat frame; // 1280×720 = 921 600 пікселів
cv::cvtColor(frame, hsv, cv::COLOR_BGR2HSV); // повний кадр

// ПІСЛЯ оптимізації:
cv::Mat small;
cv::resize(frame, small, cv::Size(320, 240), 0, 0, cv::INTER_LINEAR);
cv::cvtColor(small, hsv, cv::COLOR_BGR2HSV); // 76 800 пікселів
```

**Компроміс:** Точність локалізації руки знижується пропорційно, але для подальшого масштабування координат назад до 1280×720 достатньо.

### Оптимізація 2 — Оптимізація морфологічного ядра + пропуск кадрів

**Файл:** `src/gesture/gesture_detector_optimized.cpp`

**Проблема:** Два окремих виклики (`erode` + `dilate`) з ядром 7×7 = 49 пікселів на операцію.

**Рішення:**
1. Замінити на `cv::morphologyEx(MORPH_OPEN)` — один виклик замість двох.
2. Зменшити ядро з 7×7 до 5×5 (25 пікселів — прийнятна якість маски).
3. Застосовувати морфологію **кожен 2-й кадр**, між кадрами використовувати кешовану маску.

```cpp
// ДО: два окремих виклики, ядро 7×7
auto kernel7 = cv::getStructuringElement(cv::MORPH_ELLIPSE, {7,7});
cv::erode (mask, mask, kernel7);
cv::dilate(mask, mask, kernel7);

// ПІСЛЯ: один виклик OPEN, ядро 5×5, кешування
static cv::Mat cached_mask;
static int frame_idx = 0;
auto kernel5 = cv::getStructuringElement(cv::MORPH_ELLIPSE, {5,5});
if (frame_idx++ % 2 == 0) {
    cv::morphologyEx(mask, cached_mask, cv::MORPH_OPEN, kernel5);
}
mask = cached_mask;
```

### Оптимізація 3 — Кешування жесту (Gesture Cache)

**Файл:** `src/gesture/gesture_detector_optimized.cpp`

**Проблема:** При статичній руці (`gesture_classify`) виконується щокадру без потреби.

**Рішення:** Порівнювати зміщення центру маси з попереднім кадром. Якщо зсув < 3 пікселів — повертати попередній жест без повторної класифікації.

```cpp
// Кешування жесту
static GestureType last_gesture = GestureType::NONE;
static cv::Point2f last_centroid;

float dx = centroid.x - last_centroid.x;
float dy = centroid.y - last_centroid.y;
if (dx*dx + dy*dy > 9.0f) { // поріг 3 пікселі
    last_gesture  = classify(contours);  // повна класифікація
    last_centroid = centroid;
}
return last_gesture; // кешований результат
```

## 8. Рекомендації для подальшої оптимізації

1. **Паралельна обробка** — запустити читання кадру та обробку попереднього кадру в окремих потоках (`std::thread` + double buffer). Очікуване покращення: 20-30%.
2. **GPU-прискорення** — OpenCV CUDA: `cv::cuda::cvtColor`, `cv::cuda::threshold`. Потребує NVIDIA GPU.
3. **MediaPipe замість HSV** — нейромережевий детектор руки, стійкіший до освітлення, але потребує ~15 мс на CPU.
4. **INTER_NEAREST для resize** — мінімальна зміна, прискорення ~2×.
